Both are EPA's published per-figure CSV format: a 5-line metadata preamble
(figure title, EPA source line, data source, web update, units) then a blank
line, then the header row, encoded windows-1252. `R/utils/epa_csv.R` reads
that format directly, so `R/build_data.R` needs no `readxl` ingestion path
here. The preamble is where `data/meta.yml`'s `figure_title`, `data_source`,
`web_update` and `unit` come from -- they are not typed anywhere by hand.

Figure 3 (the 1996-vs-2022 dot maps) has **no published data file**. EPA
publishes the maps as images only, so there is no third CSV to record and no
third dataset in `data/`. `R/gen_page.R` renders that figure from the image
embedded in the archived Word document instead.

`lyme_11-22-24.docx` is the one `R/gen_page.R` was run against: it carries the
prose, all three figure captions, all three figure images, and the 12
references. The technical documentation contains no figures of its own, so
`R/gen_page.R`'s one-docx-per-run limitation does not bite here. It is still
the only source for one fact the page carries -- the 2021 COVID-19 caveat in
`data/lyme_incidence_national.csv`'s `note` column, which appears in the TD's
"Comparability Over Time and Space" section and nowhere else.

Two reasons: the prose lives in `index.qmd` (generated by `R/gen_page.R`,
see below), which is the artifact the site renders -- keeping a second copy
in a binary format invites the two to disagree. And the docx itself may
carry tracked changes, `word/comments.xml`, or `word/people.xml`, so
committing it risks publishing reviewers' names and internal editorial
comments that are not part of the published page.

`R/gen_page.R` reads directly from the archived docx to generate `index.qmd`
and to auto-extract each figure's own image. Once `index.qmd` is generated
and reviewed, the docx is out of the loop -- `index.qmd` is the source of
truth from then on, and rerunning `R/gen_page.R` will happily overwrite it
again, so treat that rerun as "start over," not "update in place."

## Updating the data

Replace the raw file(s) in this folder and rerun `R/build_data.R`. The build
should read headers/sheet names to identify series rather than relying on
column position, so an update flows through automatically and a renamed or
reordered column stops the build with a clear error instead of silently
mismatching a series (see `assert_headers()` / `assert_conservation()` in
`R/utils/epa_csv.R`, reused or mirrored by `R/build_data.R`). Update the
table above with the new sha256 and note the new EPA "Web update" date.
